## Offline adaptive backend candidate and combined preview

`lib/adaptive-hls.js` now packages an explicitly approved source into completed VOD HLS media. It encodes 360p/480p/720p/1080p independently when the source has enough pixels; it does not upscale lower resolution sources or advertise missing profiles. Each profile has its own AVC video and AAC audio rendition per available audio track (up to eight). Four second fMP4 video segments have fixed keyframe boundaries, and the packager verifies aligned segment durations before it writes the master. The master bandwidth values are measured from encoded segments and include the largest available audio rendition for that profile. A source change changes the cache key. Completed packages are atomically published and reused; playback only serves files listed by a completed package. Byte ranges and HEAD are supported. An exclusive file lock allows one encoder job per cache root, with a total deadline, size/free space checks, a hard FFmpeg output limit, one FFmpeg child at a time, and explicitly constrained decoder/filter/encoder threads. Incomplete packages are never advertised. A remote HTTP/FTP input must have an explicitly approved hostname and source fingerprint; it is staged once as a bounded local Matroska copy, then all renditions are encoded locally. HTTP redirects are disabled. This was tested with a loopback HTTP source, not a real FTP/BDIX title.

The branch's desktop `PlayerSession` now exposes manual Auto/360p/480p/720p/1080p choices when Hls.js reports multiple actual levels. It sets `hls.loadLevel`, so a manual switch applies to future fragments and does not flush the current buffer or seek. The selection survives HLS reattachment. A completed seek while paused returns to `PAUSED`. Native Safari HLS has no equivalent manual level control in this candidate, so the menu is hidden there. The existing direct playback path is unchanged.

The repository `server.js` is not a deployable integration target for this candidate: its desktop `/api/playback/local/:id` path forcibly returns a direct plan, while the running frontend uses `/api/playback/:id` and `/api/playback/remote` capability paths. The deployed Mac mini backend bytes were not available for comparison because read-only SSH to `streamvault-mini` timed out and the local Tailscale client reported `Stopped` with no online target peer. The production backend must be audited and the completed-cache capability and media routes wired into its exact code before deployment. No production endpoint, credentials, Mac mini service, or data were changed. Original quality direct play remains a required acceptance gate.

For the isolated preview, run `SV_ADAPTIVE_PREVIEW_SOURCE=/absolute/approved/local/movie.mp4 SV_ADAPTIVE_PREVIEW_CACHE=/absolute/private/cache node scripts/adaptive-hls-preview.js` and, in another terminal, `python3 -m http.server 8765 --bind 127.0.0.1 --directory hostinger`. Open `http://127.0.0.1:8765/adaptive-preview.html`; the page uses this branch's real `PlayerSession` and Hls.js against the pre-encoded loopback backend at `127.0.0.1:8766`. The cache directory must be owner-only, the preview has no public encode route, binds only to loopback, and rejects other browser origins. Its pre-encode step blocks startup until all files validate. The existing `http://127.0.0.1:8765/` frontend preview remains available. The local preview backend is a separate process and does not replace or restart production.

### Recorded evidence and limits

The 60 second 1920×1080 synthetic, two audio track local source generated this **v2** master (peak and average bits per second, video plus maximum audio track):

| Variant | Resolution | Peak | Average | Segments |
| --- | ---: | ---: | ---: | ---: |
| 360p | 640×360 | 419,154 | 334,540 | 15 |
| 480p | 854×480 | 830,695 | 724,647 | 15 |
| 720p | 1280×720 | 2,027,778 | 1,817,023 | 15 |
| 1080p | 1920×1080 | 4,055,204 | 3,658,482 | 15 |

The complete package occupied about 50 MiB. The cache root must be owner-only. `ffprobe` confirmed AVC dimensions for every variant; the test suite parsed and compared all 15 video segment boundaries, both audio track playlists per variant, cache reuse, a lock conflict, HTTP byte ranges, and a loopback HTTP remote stage with a subtitle stream before the audio streams. The 12 second local benchmark completed all four video and eight audio encodes in 21.7 seconds on this development Mac, sampled peak FFmpeg CPU 205.3% and peak resident memory 199 MiB. This is a local sample, not Mac mini capacity. An earlier looser thread configuration peaked at 466.8% CPU and 295 MiB; it was replaced before the v2 package was built.

Chrome with cache disabled and DevTools network emulation showed Auto selecting 360p at 500 Kbps and 1 Mbps, 720p at 5 Mbps, and 1080p at 20 Mbps on the **v1** sample package (before the stricter thread setting, which changes encoding resource use but keeps rendition targets). Recorded startup to `READY` was 12.562 s, 11.508 s, 8.744 s, and 7.814 s respectively. At 500 Kbps, media time reached 27.01 s with 20.99 s buffered and no recorded stall in the observed window. A roughly six second simulated disconnect produced two nonfatal fragment load errors; after restoring 500 Kbps, media time advanced to 33.64 s with no recorded stall. Paused seeking, manual quality, alternate audio selection, and 1.5× speed controls were exercised; pause intent stayed false for playback after the seek. The v2 package was then reopened in Chrome and played to the end of the 60 second clip with no reported stall or HLS error at unthrottled local speed. Browser audio correctness and lip sync were not independently measured.

These measurements are not controlled before/after comparisons against the production single variant: the production baseline used an FTP-backed title and a separate production backend, whereas the adaptive preview used a local synthetic source over loopback. The baseline observation remains about 7.7 media seconds over 40 wall seconds after an uncached seek at simulated 500 Kbps. No ten minute run, Safari run, real mobile data run, real FTP/BDIX title, series title, subtitle switching, Mac mini CPU/RAM, or deployment acceptance was completed. Production status remains **unverified**.

Focused verification: `npm run test:adaptive-hls`, `npm run test:desktop-network-recovery`, `npm run test:frontend-playback-session`, `npm run test:audio-language`, `npm run test:audio-playback-regression`, and `npm run test:modal-ui` passed.
